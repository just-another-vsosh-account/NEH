# NEH - Расширенные honeypot-механизмы на базе Nginx

Прототип реализации продукта, описанного в `pz.txt`.

NEH объединяет:

- SIEM-ориентированный шлюз для сбора событий и отвлечения трафика
- URL-knocking в модуле фазы доступа Nginx
- honeypot-веб-сервис для подозрительного трафика
- структурированное логирование событий в JSON
- связку Filebeat -> Elasticsearch -> Kibana для наблюдаемости
- демонстрационные сценарии для легитимного пользователя и атакующего

## Структура репозитория

- `docker-compose.yml` - единый compose-файл для всех демонстрационных режимов
- `nginx-module/` - пользовательский модуль Nginx и сборка образа
- `nginx/` - конфигурация Nginx для демонстрации
- `honeypot/` - лёгкий honeypot на Flask
- `protected-app/` - имитация защищённого административного сервиса
- `filebeat/` - конфигурация Filebeat
- `telegram-bot/` - Telegram-бот для SIEM-сводок
- `scripts/` - демонстрационные скрипты
- `lab/` - сценарии демонстрации и тестирования
- `lab/kibana/` - пакет импорта saved objects для Kibana

## Демонстрационный сценарий

Защищённый ресурс: `/admin`

Последовательность knock-запросов:

1. `/start`
2. `/verify`
3. `/grant`

Поведение:

- Клиент, который выполняет последовательность в правильном порядке и в пределах таймаута, получает временное окно доступа к `/admin`.
- Прямой запрос к `/admin` без авторизации внутренне перенаправляется в honeypot.
- Попытки knock-доступа и решения системы логируются в JSON.
- Filebeat отправляет логи edge-сервиса и honeypot в Elasticsearch.

## Быстрый старт

Минимальная лаборатория:

```bash
docker compose up --build -d gateway honeypot protected-app
```

Базовый SIEM-стек:

```bash
docker compose up --build -d
```

Затем:

```bash
./scripts/demo_user.sh
./scripts/demo_attack.sh
```

Точки доступа:

- Входная точка gateway: `http://localhost:8080`
- Kibana: `http://localhost:5601`
- Elasticsearch: `http://localhost:9200`
- Telegram-бот: `/status`, `/recent`, `/dashboard`
- Алертинг honeypot: автоматическое уведомление в Telegram, если один IP превышает настроенный порог запросов

Необязательная демонстрация модуля Nginx:

```bash
docker compose --profile nginx-module up --build -d nginx honeypot protected-app
```

- Входная точка модуля Nginx: `http://localhost:8081`

## Примечания

- Это демонстрационный прототип, рассчитанный на лабораторную среду.
- Модуль хранит состояние по IP в shared memory Nginx.
- Предоставленная конфигурация Nginx направляет подозрительный трафик в honeypot и открывает защищённое приложение только после успешной knock-последовательности.

## На что делать акцент при демонстрации

Рекомендуемая последовательность живой демонстрации:

1. Покажите, что прямой доступ к `/admin` уходит в honeypot.
2. Покажите, что правильная knock-последовательность открывает `/admin`.
3. Запустите простой сканер или скрипт атакующего.
4. Покажите события в Kibana:
   - IP-адреса с наибольшим числом запросов
   - наиболее часто запрашиваемые URI
   - события перенаправления в honeypot
   - события успешной разблокировки

## Базовая SIEM-конфигурация

`docker-compose.yml`

- режим по умолчанию: gateway, honeypot, protected app, Filebeat, Elasticsearch, Kibana и автоматический импорт дашборда
- в режиме по умолчанию также запускается Telegram-бот, ограниченный настроенным списком Telegram ID
- дашборд по умолчанию: `Демо-дашборд NEH` импортируется в Kibana автоматически
- необязательный профиль `nginx-module`: демонстрация пользовательского C-модуля Nginx на порту `8081`
