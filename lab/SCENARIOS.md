# Варианты демонстрационной лаборатории

## Минимальная лаборатория

Используйте базовый gateway-стек из `docker-compose.yml` на одной машине.

Что показать:

1. Прямой запрос к `/admin` попадает в honeypot.
2. Правильная последовательность `/start -> /verify -> /grant` открывает `/admin`.
3. Запросы атакующего к случайным путям собираются honeypot.
4. События появляются в Kibana.

Это самый простой вариант демонстрации для защиты проекта.

Запуск:

```bash
docker compose up --build -d gateway honeypot protected-app
./lab/run_demo.sh
```

## Лаборатория с тремя ролями

Используйте три виртуальные машины:

1. VM защитника
   - Docker
   - стек NEH
2. VM атакующего
   - `curl`
   - `ffuf`, `dirb` или `gobuster`
3. VM пользователя
   - браузер или `curl`

Последовательность демонстрации:

1. Запустите перебор директорий с VM атакующего.
2. Параллельно выполните правильную knock-последовательность с VM пользователя.
3. Покажите, что:
   - трафик атакующего уводится в сторону
   - легитимный доступ продолжает работать
   - логи разделяются по IP-источнику

## Лаборатория для blue team

Используйте четыре узла:

1. Edge-сервис с NEH gateway или опциональным модулем Nginx
2. Honeypot-приложение
3. Защищённое админ-приложение
4. Elastic Stack

Ключевые тезисы:

- фильтрация в access phase Nginx
- обман через внутренний redirect
- JSON-логирование и сбор событий
- живой мониторинг в Kibana

Запуск:

```bash
docker compose up --build -d
```

## Сценарии тестирования

### Функциональные

1. Правильная knock-последовательность в пределах таймаута открывает доступ.
2. Неправильный порядок отправляет клиента в honeypot.
3. Превышение таймаута между шагами сбрасывает последовательность.

### Атакующие

1. Прямой запрос к `/admin` без knock-доступа.
2. Сканирование `/`, `/admin`, `/phpmyadmin`, `/backup`.
3. Попытки перебора правильного порядка knock-запросов.

### Мониторинг

1. Создайте представление Kibana Lens для `decision`.
2. Создайте график Top values для `remote_addr`.
3. Создайте график Top values для `uri` и `original_uri`.
4. Создайте алерт, когда число перенаправлений в honeypot с одного IP превышает порог.
