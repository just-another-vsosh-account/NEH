# Руководство по лаборатории NEH

## Вариант 1: Быстрая демонстрация

Используйте этот вариант, когда нужна быстрая защита:

```bash
docker compose up --build -d gateway honeypot protected-app
./lab/run_demo.sh
```

Что показать:

1. Прямой запрос к `/admin` возвращает страницу honeypot.
2. `/start`, `/verify`, `/grant` возвращают `204`.
3. После этого `/admin` открывает защищённое приложение.

## Вариант 2: Полная лаборатория для blue team

Используйте этот вариант, когда нужны скриншоты SIEM и мониторинг:

```bash
docker compose up --build -d
```

Затем:

1. Откройте Kibana по адресу `http://localhost:5601`
2. Откройте импортированный `Демо-дашборд NEH`
3. Убедитесь, что существует data view `neh-events-*`
4. Следуйте инструкциям из [KIBANA.md](/home/ilyastarcek/vsosh/lab/KIBANA.md)

## Роли

### Защитник

- запускает стек NEH
- следит за логами и дашбордами

### Легитимный пользователь

- выполняет известную knock-последовательность
- получает доступ к `/admin`

### Атакующий

- сканирует случайные пути
- попадает в honeypot
- должен запускаться с отдельного хоста или после истечения окна доступа, если нужна чистая изоляция IP

## Рекомендуемый сценарий выступления на защите

1. Сформулируйте проблему: обычные honeypot не помогают, если реальный URL уже известен.
2. Покажите решение: NEH размещает honeypot на той же входной точке и открывает реальный сервис только после URL knocking.
3. Покажите рядом поведение пользователя и атакующего.
4. Покажите подтверждение в логах и на дашборде.

Примечание:

- Лаборатория по умолчанию использует Python gateway как SIEM-ориентированный edge-сервис.
- Реализация на C для Nginx остаётся доступной через профиль `nginx-module`.
